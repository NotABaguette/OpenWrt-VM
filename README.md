# OpenWrt ESXi Template Builder

Builds a VMware-friendly OpenWrt x86_64 template from the latest official OpenWrt image using GitHub Actions, then publishes the generated assets to GitHub Releases.

The workflow produces:

- `.ova` — recommended import format for ESXi/vCenter.
- `.ovf` + `.vmdk` — unpacked OVF template pair.
- `.iso` — offline artifact bundle containing the OVF/VMDK files. This is **not** an OpenWrt installer ISO.
- original upstream `.img.gz` — downloaded from OpenWrt.
- `SHA256SUMS` and `metadata.json`.

## Why OVA/OVF instead of a real installer ISO?

OpenWrt x86 is distributed primarily as disk images, such as `generic-ext4-combined-efi.img.gz`. For ESXi, the practical path is to convert the disk image to VMDK and wrap it in an OVF/OVA template.

The ISO generated by this repo is only a transfer bundle for environments where uploading an ISO is easier than uploading multiple files.

## Repository setup

1. Create a new GitHub repository, for example:

   ```bash
   gh repo create openwrt-esxi-template-builder --public --clone
   ```

2. Copy these files into the repository.

3. Push:

   ```bash
   git add .
   git commit -m "Add OpenWrt VMware template builder"
   git push origin main
   ```

4. In GitHub, enable Actions if prompted.

5. Make sure workflow release publishing is allowed:

   ```text
   Repository → Settings → Actions → General → Workflow permissions
   Select: Read and write permissions
   Save
   ```

## Run manually

Go to:

```text
Actions → Build OpenWrt VMware Template → Run workflow
```

Inputs:

| Input | Example | Description |
|---|---:|---|
| `openwrt_version` | `latest` | Use `latest`, `snapshot`, or an exact stable version like `25.12.4`. |
| `image_variant` | `efi` | `efi` is recommended for modern ESXi. Use `bios` only if needed. |
| `disk_size` | `4G` | Expands the virtual disk container before VMDK conversion. Leave empty to keep upstream size. |
| `prerelease` | `false` | Marks the GitHub Release as prerelease. Snapshots are always prereleases. |

## Scheduled builds

The workflow runs weekly on Sunday at 03:17 UTC. Scheduled builds use:

```text
openwrt_version = latest
image_variant   = efi
disk_size       = 4G
```

If the release tag already exists, the workflow updates the release notes and replaces assets with `gh release upload --clobber`.

## Generated release tags

Stable example:

```text
openwrt-25.12.4-efi
```

Snapshot example:

```text
openwrt-snapshot-20260605-efi
```

## Import into ESXi 6.7 U3

Use the `.ova` asset first:

```text
ESXi Web UI → Virtual Machines → Create / Register VM → Deploy a virtual machine from an OVF or OVA file
```

Recommended first-boot VM checks:

```text
Firmware: EFI for efi builds, BIOS for bios builds
NIC: E1000e by default
Disk controller: LSI Logic
Network: attach to the correct ESXi port group
```

## Default OpenWrt behavior

Fresh upstream OpenWrt images usually boot with:

```text
LAN IP: 192.168.1.1
User: root
Password: empty until you set one
```

Immediately set a password after first boot:

```sh
passwd
```

If this VM will sit behind your MikroTik and act as a secondary gateway, change its LAN IP, disable DHCP, and set the MikroTik as the gateway. Example:

```sh
uci set network.lan.ipaddr='192.168.88.2'
uci set network.lan.netmask='255.255.255.0'
uci set network.lan.gateway='192.168.88.1'
uci set network.lan.dns='1.1.1.1 8.8.8.8'
uci commit network
/etc/init.d/network restart

uci set dhcp.lan.ignore='1'
uci commit dhcp
/etc/init.d/dnsmasq restart
```

## Local build

You can run the same build locally on Debian/Ubuntu:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates coreutils curl gzip jq qemu-utils tar xorriso

OPENWRT_VERSION_INPUT=latest \
IMAGE_VARIANT=efi \
DISK_SIZE=4G \
scripts/build-openwrt-template.sh
```

Artifacts will be written to `dist/`.

## Customization via environment variables

The script supports these environment variables:

| Variable | Default | Purpose |
|---|---:|---|
| `BASE_URL` | `https://downloads.openwrt.org` | OpenWrt download base URL. |
| `OPENWRT_VERSION_INPUT` | `latest` | `latest`, `snapshot`, or exact stable version. |
| `IMAGE_VARIANT` | `efi` | `efi` or `bios`. |
| `DISK_SIZE` | `4G` | Optional virtual disk size. |
| `VM_NAME` | `OpenWrt` | VM name in the OVF descriptor. |
| `VM_NETWORK` | `VM Network` | OVF logical network name. |
| `VM_CPUS` | `2` | vCPU count in OVF. |
| `VM_MEMORY_MB` | `512` | RAM size in OVF. |
| `NIC_MODEL` | `E1000e` | Virtual NIC model in OVF. |
| `VM_HW_VERSION` | `vmx-13` | Virtual hardware version for ESXi compatibility. |

Example:

```bash
VM_NAME=OpenWrt-Gateway \
VM_NETWORK=LAN \
VM_MEMORY_MB=1024 \
DISK_SIZE=8G \
scripts/build-openwrt-template.sh
```

## Notes and limitations

- The workflow verifies the downloaded OpenWrt image against OpenWrt's `sha256sums` file.
- Expanding the virtual disk container does not automatically expand OpenWrt's root filesystem inside the image. Resize inside OpenWrt after boot if you need the extra space.
- The generated OVF is intentionally simple: one disk, one NIC, E1000e, LSI Logic, small CPU/RAM footprint.
- For multi-NIC router templates, clone the VM after import and add NICs from the ESXi UI so you can control port-group ordering safely.
